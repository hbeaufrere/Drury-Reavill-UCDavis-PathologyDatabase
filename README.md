# Drury R. Reavill Pathology Database at UC Davis

A web application for exploring the Drury R. Reavill exotic companion animal
pathology archive: ~84,000 pathology reports and ~1,500 cytology cases across
birds, reptiles, small mammals, amphibians, and fish.

Built with **Next.js** (deployed on Vercel) and **Neon Postgres**.

## Features

- **Landing page** with headline statistics and taxon/species distributions
- **Search** — full-text and/or term search across selectable columns, with
  filters for taxon, species/breed, sex, body system, disease process,
  service type, and age range
- **Charts** — bar, donut, histogram, box plot, scatter, and heatmap, all
  driven by the current filters and computed in SQL
- **Data summary** — per-column completeness and statistics
- **CSV export** of any filtered result set
- **Anonymized by default** — patient names are stored in the database but
  never returned to public visitors; signing in at `/admin` with the admin
  password reveals them (there is no clinic-name column in the source data)

## Architecture

```
app/                  Next.js App Router pages and API routes
  page.tsx            Landing page (server-rendered stats, revalidated hourly)
  explore/            Search / charts / data summary UI
  admin/              Admin sign-in (reveals patient names)
  api/                meta, records, chart, summary, export, admin/login
components/           UI components (filter panel, table, charts)
lib/                  DB driver wrapper, filter/SQL builder, auth, labels
scripts/
  prepare_seed.py     parquet -> cleaned data/*.ndjson.gz (run when data changes)
  seed.mjs            data/*.ndjson.gz -> Postgres (npm run db:seed)
data/                 Committed seed files generated by prepare_seed.py
*.parquet             Original source data (unchanged)
```

The database driver is chosen automatically: the Neon serverless HTTP driver
when `DATABASE_URL` points at Neon, a regular `pg` pool otherwise (local
development, any other Postgres).

## Setup

### 1. Create the Neon database

Create a free project at [neon.tech](https://neon.tech). You will need two
connection strings from the project dashboard:

- the **pooled** connection string (hostname contains `-pooler`) — for the app
- the **direct** connection string — for seeding

### 2. Seed the data

```bash
npm install
DATABASE_URL="<direct connection string>" npm run db:seed
```

This creates the `records` table, loads all 85,734 rows, and builds the
b-tree and trigram indexes (the `pg_trgm` extension is enabled automatically).
Re-running it drops and rebuilds the table.

If the parquet files ever change, regenerate the seed files first:

```bash
python3 scripts/prepare_seed.py   # needs: pip install pandas pyarrow
```

### 3. Configure Vercel

In the Vercel project settings, add two environment variables:

| Variable | Value |
|---|---|
| `DATABASE_URL` | the **pooled** Neon connection string |
| `ADMIN_PASSWORD` | a password of your choice; unlocks patient names at `/admin` |

Then redeploy. Without `DATABASE_URL` the site renders a setup notice instead
of data; without `ADMIN_PASSWORD` admin mode is simply disabled.

## Local development

```bash
npm install
DATABASE_URL="postgres://...local or Neon..." ADMIN_PASSWORD=dev npm run dev
```

## Data cleaning

Applied once at seed time by `scripts/prepare_seed.py` (the parquet originals
are untouched): whitespace normalization, removal of Excel `_x000D_`
line-break artifacts, normalization of obvious typos in sex and body-system
values, and ages above 200 years treated as data-entry errors (stored as
unknown). `cyto_reports.parquet` is a byte-for-byte duplicate of
`reports_main.parquet` and is not loaded separately.
